# WMS 创新功能设计方案 (WMS Innovative Features Design)

## 1. 现状分析
当前的系统（Watercup WMS）已经具备了 ERP/WMS 的坚实骨架：
- 完整的出入库（Inbound/Outbound）单据流转与审核机制（强一致性事务）。
- 基础的 2D 库位热力图（Visual Warehouse）和 Echarts 数据看板。
- 基础数据与系统权限（RBAC）管理。

**缺失的执行层能力**：系统目前更像是一个“库存记账系统”，缺乏指导仓库现场工人“怎么搬、怎么捡、怎么扫”的执行层（Execution）能力。

---

## 2. 创新性功能设计：智能波次拣货与 3D 路径规划 (Smart Wave Picking & 3D Routing)

为了让系统真正具备“智慧仓储”的创新性，我设计了以下核心模块。这不仅填补了 WMS 的空白，还引入了算法优化，极大地提升了系统的演示效果和实用价值。

### 2.1 智能波次管理 (Smart Wave Management)
传统 WMS 是一单拣一次，效率极低。波次管理是将多个相似的出库单（例如：同一承运商、同一客户、包含相同物料的单子）合并成一个“波次（Wave）”，让拣货员推着小车一次性拣完多单的货。

**功能亮点**：
- **AI 聚合建议**：系统自动分析当日未处理的出库单，按“库位重合度最高”或“物料重合度最高”自动推荐波次组合。
- **播种式分拣 (Put-to-light concept)**：拣货完成后，在复核台通过扫码（或系统指引）将总货品分发到各个订单的打包箱中。

### 2.2 3D 视觉仓库与拣货最优路径 (3D Visual Warehouse & Optimal Routing)
将现有的 2D CSS Grid 库位图升级或结合，提供一个面向拣货员的“动态路径图”。

**功能亮点**：
- **拣货地图指引 (Pick Map)**：在生成波次拣货单时，系统根据库位坐标（X排-Y列-Z层），利用 TSP（旅行商问题）或简单的 S 型路线算法，计算出拣货员在仓库里走动的**最短路径**。
- **可视化输出**：在前端渲染一张仓库俯视图，用动画线条连接需要去拣货的库位，并在节点上标明“先去A1拿2个，再去B3拿5个”。

### 2.3 PDA / 移动端扫码工作台 (Mobile Scanner Workbench)
WMS 的灵魂在于现场扫码。
- **功能亮点**：利用 HTML5 的 `navigator.mediaDevices.getUserMedia` 调用摄像头，在浏览器端实现一个纯前端的扫码模拟器。现场工人只需用手机浏览器打开该页面，对准货物条码（或系统生成的模拟二维码）即可完成复核、入库上架、盘点。

## 3. 迭代实施计划 (Implementation Plan)

在不破坏现有稳定架构的前提下，我们进行以下增量迭代：

### 阶段一：波次拣货模块 (后端 + 前端)
1. **数据库设计（虚拟/实际）**：新增 `Wave` (波次主表) 和 `WaveDetail` (波次明细表)。
2. **后端 API**：在 `server/routes/outbound.js` 旁新增 `wave.js` 路由，提供波次生成、波次审核、波次拣货完成的接口。
3. **前端页面**：在 `src/views/home/components/OutStorage` 下新增 `WavePicking.vue`。

### 阶段二：最优拣货路径算法与可视化 (前端)
1. **算法引入**：在前端 `utils/routing.js` 中实现一个简易的路径排序算法（按排、列顺序排序）。
2. **可视化组件**：开发 `PickPathMap.vue` 组件，使用 Canvas 或现有的 Echarts 绘制带有行进路线的仓库平面图。

### 阶段三：模拟扫码工作台 (前端)
1. **前端页面**：新增 `MobileScanner.vue`，作为独立路由或弹窗，模拟 PDA 的扫码枪输入逻辑（监听回车键或调用摄像头解析器）。

---
*注：由于当前环境没有 MySQL 实例，后端接口将在代码层面完全实现并使用 mock 数据或容错机制供前端 UI 渲染和交互。*
